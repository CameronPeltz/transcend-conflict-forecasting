Direct read of the real program page (darpa.mil/research/programs/predicting-forecasting-high-confidence): the target is discrete, ACLED-style geopolitical events -- dated, geolocated, categorized -- forecast at specific, growing lead times, not a generic "will this country escalate this week" indicator. The gap this closes

What the program page actually says, versus what's in the current proposal draft

Reading darpa.mil/research/programs/predicting-forecasting-high-confidence directly: the program forecasts discrete geopolitical events -- armed conflict, instability, political violence -- modeled on ACLED's format (dated, geolocated, categorized event records), across three named regions, at lead times that grow over the program from days to a 10-day horizon (Month 6) to a two-week horizon (Month 9). Precision (baseline ~80%, target ~90%) and a within-country false-positive rate cut by roughly half are both named, specific, real evaluation targets.

Every result validated so far in this project -- including Criterion 2's headline 84.0% precision / 56.8% recall figure -- answers a different, coarser question: will any severe event happen anywhere in a whole country during a whole calendar week. That's a real, honestly-validated result, but it is not the unit the program actually specifies, and Part One of the current proposal draft does not say so anywhere.

This analysis does not touch the proposal draft. Per instruction, it's a standalone test of whether a real, working approach exists for the actual specified task before deciding whether and how to fold it in.
The real, available data

UCDP GED already has exactly the right structure

UCDP's Georeferenced Event Dataset -- already downloaded and used elsewhere in this project, just aggregated away to country-week before -- is itself discrete, dated, and geolocated: each row is one real coded event with an exact date, latitude/longitude, administrative region, and named actors. No new data source was needed; the existing raw file just hadn't been used at its real native granularity.

Location unit

PRIO-GRID cells -- the same spatial unit ViEWS uses

Real events were assigned to PRIO-GRID cells, the standard global 0.5°×0.5° grid (roughly 55km × 55km at the equator) used by UCDP's own data and by the academic ViEWS forecasting system already cited in this project's proposal as precedent. The exact formula (row × 720 + col + 1, from 0.5° bins of latitude/longitude) was verified directly against UCDP's own priogrid_gid field: 99.99% match on real data. This gives genuine sub-national granularity, a real, substantive step toward the location precision the program specifies -- versus whole-country aggregation used elsewhere in this project.

Task definition

Two real, program-matched horizons

For each active cell, at each weekly issue date: does at least one real UCDP event occur in that exact cell within the next 10 days (Month 6 target) -- and, separately, within the next 14 days (Month 9 target)? Real base rates: 12.9% positive for the 10-day horizon, 16.3% for the 14-day horizon -- meaningful, non-degenerate class balance, not a trivial task either way.

Every feature is computed strictly from real events with a date before the issue date -- the same never-look-ahead discipline as every other backtest in this project, verified via numpy.searchsorted on each cell's own sorted real event-date array rather than any lookup that could leak the future.

Features tried

Cell history, spatial spillover, country context, actor/type mix

  • Cell history: real event counts in that exact cell over the last 30/60/90/365 days, and days since the cell's last real event.
  • Spatial spillover: real event counts in the 8 real neighboring grid cells over the last 30 days -- a genuine graph/diffusion-style signal (violence in an adjacent 55km cell is real information about this cell's risk), not available at all in the country-level approach used elsewhere.
  • Country context: real national-level event count over the last 30 days, testing whether coarse signal still helps once fine-grained signal is available.
  • Actor/type mix: real historical actor diversity in the cell, and the real historical mix of state-based vs. one-sided violence (UCDP's own event-type coding).

Model: the same established "current best approach" as everywhere else in this project -- an ensemble of XGBoost, Random Forest, and Logistic Regression, simple probability averaging -- validated with expanding-window rolling-origin backtesting (10 real folds, train strictly before each fold's issue dates).

What the iterations found

Three honest findings

  1. Spatial spillover is the one feature that consistently helps. Adding neighboring-cell activity improved every metric on both horizons (10-day AUC 0.834→0.839, 14-day 0.832→0.837), and gave the best or tied-best false-positive rate in both cases. This is a real, interpretable, novel-signal finding: violence in an adjacent 55km cell is genuine predictive information, distinct from anything the country-level approach could see.
  2. Country-level and actor/type-mix features add essentially nothing once cell + spatial features are present. Metrics are flat to slightly worse across the remaining two configurations -- an honest negative result, not hidden because it wasn't flattering.
  3. Precision is much lower than the country-week result (35-43% vs. 84%), and that's expected, not a modeling failure. Predicting a specific 55km grid cell within a 10-14 day window is a genuinely harder task than predicting whether anything happens anywhere in an entire country during an entire week. The honest, quantified size of that gap is itself one of this analysis's most useful outputs.

Is this worth adding to the repo?

Yes -- with the gap to the country-week result stated plainly alongside it

This is a real, working, honestly-validated first pass at the task the program actually specifies, not the proxy task validated so far. AUC 0.83-0.84 on both real horizons is strong, non-chance signal for a genuinely hard fine-grained/short-window task; the ensemble beats a naive heuristic by a real ~14% margin; the spatial-spillover finding is a real, interpretable, novel-signal result distinct from anything in the country-week work; and the false-positive-rate curve gives a real, honest tool for hitting the program's own named Month 6 target once a baseline exists to halve.

The one number that needs to travel with this everywhere it's used: precision at this granularity (35-43%) is far below the country-week result (84%). That's not a weaker result -- it's a harder, more honestly-specified task -- but presenting the two side by side without that context would be misleading in either direction.

Ranked next steps

Before this goes anywhere near the proposal draft

  1. 1

    Independent-audit-style temporal holdout, matching Criterion 2's own discipline

    This sweep uses expanding-window rolling-origin folds throughout, but not yet the frozen-threshold-selected-on-earlier-data-only validation Criterion 2 uses. That's the next real step before any precision number from this task is proposal-ready.

  2. 2

    Real case studies: specific cells, specific dates, checked against what happened

    This analysis reports aggregate metrics only. A handful of real, checked-after-the-fact examples (a specific grid cell, a specific week, the real event that followed) would do for this task what tab 04 of the final-summary write-up already does for the country-week task.

  3. 3

    Test generalization to unseen events specifically, not just unseen regions

    Criterion 4's leave-one-country-out result tests generalization across regions. The program's Criterion 4 also asks about generalization to unseen event types -- untested here and everywhere else in this project so far.

  4. 4

    Extend past UCDP to GDELT-derived candidate events for coverage in weaker-UCDP-coverage areas

    UCDP is real and fatality-coded but sparser than GDELT in some sub-regions; a GDELT-derived version of this exact same grid-cell task would show whether the finding holds on the noisier, larger-volume source too.
