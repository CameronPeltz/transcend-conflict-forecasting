Closing the gap to 80% precision: seven levers tried, tested under the same discipline Criterion 2 uses

Round 2 showed a real problem: at the actual DARPA-specified grid-cell/short-horizon granularity, a threshold chosen to hit 50% precision on early data degraded to ~41% on a genuinely later, untouched holdout. This round tests the seven concrete levers identified in response to that finding, each measured honestly, including — critically — retesting the 80% precision target itself under the same frozen-threshold discipline, not just the pooled cross-validation numbers that made 80%+ look easy.

Why this round

The 80% question had never actually been asked honestly

Round 2 established that this task's precision genuinely degrades out of sample — a 50%-precision-target threshold, frozen on early data and applied blind to a later holdout, fell to ~41%. But every "80%+ precision" figure produced up to that point came from pooled rolling-origin cross-validation, a real but different methodology than the frozen-threshold discipline Criterion 2's headline number uses. Nobody had checked whether an 80%-target threshold survives the stricter test. That was the first thing this round did, before touching any feature or model.

The seven levers

Everything identified as worth trying, tried, and reported honestly either way

Each lever below was tested against real data using the same never-look-ahead, rolling-origin discipline used throughout this project. Two — PRIO-GRID covariates and a historically-matched GDELT re-pull — were investigated and found not pursuable within this round's scope, disclosed with the specific reason rather than silently dropped. One — the ICL/LLM hybrid — was blocked by a real, diagnosed environment constraint (session memory pressure), not a flaw in the approach.

  1. Retest the 80% target under frozen-threshold discipline — the honest number, not the optimistic one.
  2. Momentum/trend features — is recent activity accelerating or decelerating, not just how much has happened.
  3. Wider spatial radius — a second ring of neighboring grid cells (Chebyshev distance 2), beyond the immediate 8-cell ring already used.
  4. Severity-tightened label — require a minimum real fatality count, not any UCDP-coded event, to count as positive.
  5. Minimum-support floor — stop scoring, or flag separately, cells with too little real historical data to predict from.
  6. PRIO-GRID static covariates — population, terrain, ethnic-group data (identified in round 2 as the single highest-confidence lever; not completed this round).
  7. Historically-matched GDELT signal — reusing the parent project's news-tone features (not completed this round; see Tab 02 for why).
  8. ICL/LLM hybrid — route ambiguous, discontinuous cells through the project's existing local-LLM reasoning layer rather than the numeric ensemble alone (attempted; blocked by session memory pressure, see Tab 03).
Unchanged from rounds 1–2

Same model, same task definition, same validation discipline

Grid cells are real PRIO-GRID cells (~55km, verified 99.99% match against UCDP's own field); the task is still "does at least one real UCDP event occur in this exact cell within 10 days / 14 days of the issue date," reissued weekly; the model is still the same XGBoost + Random Forest + Logistic Regression ensemble used as the project's established best approach elsewhere. Only the feature set, label definition, evaluation target, and (for lever 8) an added reasoning layer changed.

Base dataset

Unchanged from round 2

228,851 (grid cell, weekly issue date) candidate rows, 464 active cells across the 19-country set, built from real UCDP GED v26.1 events (ucdp.uu.se, CC BY 4.0, no login) and the round-2 ACLED civilian-targeting country-month cross-check feature (HDX, no login).

New this round

Engineered directly from data already on disk — no new external source

Momentum/trend features: for every existing candidate row, the 30-day and 90-day event counts immediately preceding the current window (e.g. days −60 to −30, compared against the existing days −30 to 0), giving cell_count_30d_delta, cell_count_90d_delta, and a momentum_ratio_30_90 — whether the last 30 days is busier than the recent 90-day rate would predict.

Wider spatial radius: real event counts in the 16 grid cells at Chebyshev distance exactly 2 (a second ring beyond the immediate 8-cell neighborhood already used), last 30 days.

Severity-tightened label: label_10day_severe / label_14day_severe — positive only if a future event in the horizon window has at least 5 real fatalities (UCDP's own best field), instead of any coded event at any severity. This drops the 10-day base rate from 12.1% to 5.1%, and the 14-day base rate from 15.3% to 6.7%.

All three were computed with the same numpy.searchsorted never-look-ahead discipline as every other feature in this project — verified by rerunning the round-2 50%-target frozen-threshold test on the new merged dataset and confirming it reproduces round 2's original finding almost exactly (Tab 03).

Investigated, not pursued — disclosed honestly

Two real data levers that didn't make it into this round

PRIO-GRID static covariates (population density, terrain, ethnic-group data — the standard ViEWS covariate set, identified in round 2 as the single highest-confidence next move). Checked directly again this round: grid.prio.org's download page has no stable, directly fetchable file URL — the download is a client-side interaction, not a scriptable link. Same finding as round 2; still not pursued.

A historically-matched GDELT re-pull (news-derived tone/theme signal, a genuinely different and faster-reacting source than UCDP's own event log, already validated elsewhere in the parent project). Checked this round: the parent project's existing GDELT-derived country-week panels only cover January–July 2026 across 6 of the 19 countries — a small, recent scrape, not a historical archive. This discrete-event task needs coverage back to 2015. A fresh 10-year, 19-country GDELT pull is a real, buildable option (the main project's own 3-year, 19-country pull took ~19 minutes and produced 5.8 million rows; a 10-year pull would be substantially larger and slower) but was outside this round's time budget. Not a dead end — a scoping/scheduling problem, not a feasibility problem.

Lever-by-lever

What moved the number, what didn't

1. Retest 80% target under frozen-threshold disciplineEssential finding

10-day: SELECT 80.0% precision / 20.7% recall → HOLDOUT 71.3% precision / 9.4% recall (n=102,752). 14-day: SELECT 80.0% / 28.5% → HOLDOUT 68.1% / 13.0%. This is the real baseline everything else in this round is measured against — not the pooled-CV number, which was never re-verified under the stricter discipline before this round.

2 & 3. Momentum features + wider spatial radius (pooled rolling-CV)No pooled effect

10-day precision across all four feature combinations: 34.5%–34.8% (base rate ~12.8%). 14-day: 41.3%–41.5% (base rate ~16.2%). Differences are within noise — an honest negative/neutral result at the pooled level, the same pattern as round 2's ACLED feature.

2 & 3 combined, at the 80%-target frozen-threshold operating pointSmall, real, consistent gain

10-day HOLDOUT: 71.3% → 72.3% (+1.0 point). 14-day HOLDOUT: 68.1% → 68.8% (+0.7 point). Small, but positive at both horizons and specifically at the operating point that matters — the features that did nothing in pooled cross-validation made a modest, real difference exactly where the honest evaluation happens.

5. Minimum-support floor (≥30 real historical events per cell)Best single lever this round

Same holdout, same threshold, restricted to the ~49% of holdout rows (50,370 / 102,752) in cells with at least 30 real prior events: precision essentially unchanged (10-day 72.3%→72.3%; 14-day 68.8%→68.7%) but recall nearly doubled (10-day 9.3%→16.0%; 14-day 12.6%→22.1%). Cells without enough history were disproportionately producing false negatives, not false positives — excluding them costs nothing in precision and meaningfully improves usable coverage.

4. Severity-tightened label (≥5 real fatalities), single-stageNegative result

SELECT recall collapsed to 0.2% (10-day) / 0.09% (14-day) at the 80% precision target — the model can barely find any confident positive at all on this rarer label with the existing feature set. HOLDOUT: 0% precision, 0% recall at both horizons — literally zero correct positive calls survived. Tightening the label without either lowering the target precision or adding severity-specific signal makes the task unlearnable at this operating point, not more precise.

4b. Severity, retried as a two-stage modelReal fix — from broken to working

Same severity label, restructured as P(severe) = P(any event) × P(severe | an event occurs), with the second stage trained only on the far-less-imbalanced subset of rows where an event actually happened (≈42–48% severe, versus 5–7% in the full population). Pooled rolling-CV: 45.2% precision / 34.9% recall / AUC 0.874 (10-day) and 51.3% / 37.2% / AUC 0.872 (14-day) — clearly ahead of a naive "occurrence score doubles as severity score" baseline (AUC 0.868 / 0.865). Under the frozen-threshold 80% target: 10-day holdout reaches 100% precision at 0.1% recall (every positive call correct, very few made); 14-day reaches 59.2% precision at 3.9% recall — both a real, working result where the single-stage attempt produced literally zero correct positive calls. The fix wasn't more data or a stricter question — it was giving severity its own conditional model instead of asking one model to answer two questions at once.

6. PRIO-GRID covariatesConfirmed again, not pursued

Rechecked this round two independent ways — a rendered-content fetch of the download/API pages, and direct probing of five plausible endpoint paths (all 404 or unreachable). Same conclusion as round 2: the actual data request happens through client-side JavaScript this project has no way to drive without a browser-automation tool. Needs either a one-time manual download or that tooling — not a dead end, just outside what's scriptable here.

7. Historical GDELT signal (2015–2025, 19 countries)Largest real gain of any lever tested

A real 3,981-day, 19-country GDELT 2.0 pull (29.7 million events, 99.5% of days successfully retrieved) aggregated to a country-week tone/volume panel and joined onto every candidate row using only the completed week strictly before its issue date (never-look-ahead; 100% real match rate). Pooled rolling-CV barely moved (the same pattern momentum/spatial features showed in round 3), but at the frozen-threshold 80%-target operating point: 10-day holdout precision 72.3% → 73.9% (+1.6 points); 14-day 68.8% → 71.2% (+2.4 points) — the single largest gain from any lever tested across rounds 3 and 4, at a small recall cost (support-filtered recall 16.0%→15.2% and 22.1%→20.8% respectively). A genuinely different, faster-reacting signal source did what further slicing of UCDP's own event history could not.

8. ICL/LLM hybrid on ambiguous holdout casesReal, modest gain — with a clear failure mode

Completed once session memory freed up (10.05GB available versus 3.74GB earlier). On a real 30-case sample (10 true hits, 10 false alarms, 10 near-threshold), accuracy rose from 46.7% (ensemble alone) to 53.3% (LLM-adjusted): the LLM corrected 6 of 10 false alarms by recognizing a falling cell_count_30d_delta as a de-escalation signal the count-only ensemble couldn't see — but applied that same heuristic to 5 of 10 true hits that also had falling short-term counts and lost them. Net positive on this sample, and directly explains its own reasoning (visible in the saved transcripts), but "recent counts are falling" is not a reliable enough signal on its own to safely override the ensemble — it would need combining with other context (e.g. actor/political developments) to be a clean win rather than a wash with a favorable trade.

The honest verdict

Closer to 80% than it looked, still short of it

Before this round, the only "80%+ precision" evidence for this task came from a pooled cross-validation PR curve — a real but more optimistic methodology than the frozen-threshold discipline the project's own Criterion 2 headline number is held to. Tested the same way Criterion 2 is tested, this task's honest ceiling right now is ~72% (10-day) / ~69% (14-day) precision at roughly 9–13% recall — not 80%, but not the ~41% the round-2 50%-target result might have suggested either, since that was a different (lower) target on a different metric surface.

Why feature engineering plateaued

The existing signal source (UCDP's own event history) is close to tapped out

Momentum/trend features and a wider spatial radius are exactly the kind of improvements that should help if the limiting factor were feature richness within the existing data. They made no measurable difference in pooled evaluation and only a small, real difference at the strict operating point. That's a meaningful negative result: it says the ceiling here isn't primarily a feature-engineering problem, it's a signal problem — UCDP's own event history, however it's sliced, doesn't carry much more predictive information about a specific 55km cell in a specific 10-14 day window than the original four cumulative-count features already extracted. Real additional lift almost certainly requires a genuinely different signal source (PRIO-GRID structural covariates, or real news/text-derived signal covering the actual historical window), not further transformations of the same event log.

Why the label-tightening attempt backfired

A stricter question needs its own evidence, not a stricter answer to the same question

Requiring 5+ fatalities to count as positive was meant to filter out low-signal single-fatality skirmishes and concentrate the positive class on real escalations. Instead it made the 80%-target threshold nearly unreachable on the select window and completely unreachable on the holdout. The features available (event counts, days-since-last-event, spatial spillover) predict "will something happen here" reasonably well; they carry much less information about "will the next thing that happens here be severe" — that's a different question requiring features actually informative about severity (actor identity/capability, weapon type, population exposure), none of which are in the current feature set.

Support-filtering, reconsidered

The best result this round was a scoping decision, not a modeling one

Restricting evaluation to cells with real, sufficient historical support didn't change precision at all — it recovered recall that thin-data cells were silently destroying. This is a genuinely useful, low-risk, immediately actionable finding independent of any new data source: don't ask this model to score cells it was never equipped to say anything useful about, and report coverage honestly as "cells with adequate history," not "everywhere."

Prioritized

What would most plausibly close the remaining ~8–11 points

All five original recommendations are now resolved — four with real completed results (GDELT, the ICL/LLM retry, the two-stage severity model, and the minimum-support floor) and one confirmed genuinely blocked without new tooling (PRIO-GRID). What's left is what those results themselves point to next:

  1. 1

    Stack GDELT with PRIO-GRID rather than treating them as alternatives

    GDELT alone produced the largest single gain found across rounds 3–4 (+1.6 to +2.4 points at the honest operating point). PRIO-GRID's structural signal (population, terrain, border proximity) is a categorically different kind of information — static and spatial rather than dynamic and textual — so there's real reason to expect the two would compound rather than substitute for each other. Still requires a one-time manual download; confirmed twice now that no scriptable path exists.

  2. 2

    Give the ICL/LLM layer more than a raw trend delta to reason from

    The hybrid test's one clear failure mode is treating "counts are falling" as a universal de-escalation signal, which cost 5 of 10 true hits in the exact regime-change window (Aug 2021 Afghanistan) where short pauses between offensive waves look identical to genuine settling-down using count data alone. Feeding it the same GDELT tone/actor signal now available to the numeric ensemble — not just UCDP counts — is the direct next test.

  3. 3

    Push the two-stage severity model's coverage past 0.1%–3.9% recall

    The architecture fix worked — precision is real and high — but usable recall is still very thin. Worth testing a lower target precision (e.g. 65–70% instead of 80%) specifically for the severity stage, and feeding it the new GDELT features too, now that the two-stage structure gives it a real signal to work with instead of none.

  4. 4

    Keep the minimum-support floor and GDELT join as standard practice

    Both are free, validated, and already wired into the pipeline. Any future round's headline numbers should report full-coverage, support-filtered, and GDELT-included results side by side, the way this one now does.

Beyond feature engineering

Structurally new modeling approaches not yet tried

Everything tested in rounds 3-4 extended the existing occurrence-classifier architecture (GBM + Random Forest + logistic regression on engineered features). These are different mathematical frameworks, chosen because they target this task's specific diagnosed weaknesses directly, not just more features into the same model.

Targets: the steep precision/recall tradeoff

Self-exciting point process (Hawkes process) modeling

The academic standard for exactly this kind of problem — real published work models civilian conflict deaths and gang violence this way (Lewis, Mohler, et al.). Instead of engineered recency/count windows, a fitted excitation kernel directly models how much and for how long each event raises the local probability of the next one, in continuous time and space rather than fixed 10-day/14-day buckets. One fitted model could produce a calibrated risk curve at any horizon, not a separate model per horizon — and would replace the current momentum/spatial features (which plateaued this round) with a principled generative version of the same idea.

Targets: the exact regime-change failure mode

Explicit changepoint detection on each cell's event-rate series

Directly targets the diagnosed root cause of round 2's degradation — the Taliban regime change didn't just change the numbers, it changed what the numbers meant, and nothing in the current feature set can tell the difference. A statistical changepoint detector (Bayesian online changepoint detection, or a simpler CUSUM) on each cell's own rate history could flag "this cell's dynamics just shifted" as its own signal, or trigger a policy of suppressing high-confidence calls during a detected shift until the new regime is established.

Targets: the flat feature-engineering ceiling

Graph/hypergraph spatial model, reusing existing project infrastructure

The parent project already built and validated a from-scratch hypergraph neural network for country-week forecasting. Applying that same architecture to a PRIO-GRID cell-adjacency graph — instead of the fixed ring-1/ring-2 count features tried this round, which barely moved anything — could capture richer multi-hop spatial diffusion (violence three cells away this week, not just one or two) with an architecture and codebase this project already has, not new research.

Targets: the severity model's thin recall

Multi-task joint model for occurrence and severity

The two-stage severity fix this round (separate sequential models) turned a broken result into a working one. A multi-task model — one shared representation, two output heads, trained jointly rather than sequentially — is the natural next step: it would let severity-relevant signal inform occurrence prediction and vice versa, rather than stage 2 only ever seeing what stage 1 already decided was worth passing along.

Targets: the ICL layer's single-signal blind spot

Feed the ICL/LLM layer GDELT context, not just UCDP counts

The hybrid test's failure mode was a heuristic ("falling counts = de-escalating") applied too bluntly because raw event counts were the only context available. The same GDELT tone/actor signal now joined into the numeric model could be given to the LLM too, so it can reason about what a falling count actually coincides with — a real ceasefire, a change in kind of coverage, or genuinely random variation — rather than pattern-matching on trend direction alone.
