Acting on the next steps: 24 more real iterations, a new best result, and what DARPA's program page actually specifies

The 157-iteration grand search (grand_search_final_writeup.html) ended with a ranked list of six concrete next steps. This round runs all six as real, backtested experiments — a stacking meta-learner, a pushed support-filter threshold, an extended two-stage severity model, a WorldPop population feature, and a combined configuration built from whichever levers actually won — then closes with the question a proposal reviewer will ask first: is this project forecasting the thing DARPA's own program page describes, and what does that page actually say?

Starting point

The six next steps this round executes

Taken directly from Tab 05 of grand_search_final_writeup.html, ranked in the order that writeup proposed them:

  1. Deploy the horizon-specific winners — tuned LightGBM (10-day, 76.1% holdout precision) and tuned Random Forest (14-day, 75.5%) — as the production backbone. Used as the comparison baseline throughout this round rather than re-run in isolation.
  2. Extend the two-stage severity architecture with the mega feature set and the new tuned models.
  3. Try LightGBM specifically for severity, given its 10-day occurrence strength.
  4. Retry WorldPop population with a proper resumable, chunked downloader.
  5. A real stacking meta-learner instead of flat probability averaging.
  6. Push the support-filtering threshold further (50, 100 historical events).
Data

Same mega dataset, same discipline

228,851 (grid cell, weekly issue date) rows, 464 real PRIO-GRID cells, 19 countries, real UCDP GED v26.1 events, 60 columns spanning every feature family built through round 5 (cell/spatial history, momentum, ACLED, GDELT, CHIRPS, UNHCR, Hawkes/CUSUM, graph diffusion). Every result below uses the same rolling-origin, never-look-ahead, frozen-threshold-at-80%-target discipline as every prior round: a chronological 60/40 select/holdout split, threshold chosen only on the select window's own out-of-fold predictions, then applied unchanged and frozen to the untouched holdout.

Real, not simulated

WorldPop: the download kept running underneath this round

The resumable downloader (next step 4) was re-run this session. It correctly skipped six already-complete, already-verified countries (Afghanistan, Myanmar, Pakistan, Tajikistan, Kyrgyzstan, Uzbekistan) and began a fresh download of Sudan, which was still in progress when this round's WorldPop experiments ran. A verification bug was caught and fixed live: the feature-extraction script originally opened each raster and read only the small windows it needed per cell, which silently "succeeded" against Sudan's partially-downloaded file by reading rows that happened to already be on disk. Adding a full-band read as a completeness check (matching the downloader's own verification standard) correctly excluded Sudan and left 214 of 464 cells (46.1%) with real, fully-verified population values — Afghanistan, Pakistan, Kyrgyzstan, and Haiti. Ethiopia, Somalia, Colombia, South Sudan, Kenya, Ecuador, and Venezuela (7 of the 12 countries with active cells) remain undownloaded; the fetch continues in the background for a future round.

Design

24 real iterations across 6 groups, one adaptive branch

Every iteration is a full frozen-threshold backtest — a real model fit on strictly-prior data at every rolling fold, never evaluated on data from before the events it predicts. 8.2 minutes total runtime. Full log: results/round6_log.jsonl; full results: results/round6_results.json.

Group A0 — 4 iterations

Solo-model controls

XGBoost and logistic regression run alone at both horizons, to give the stacking meta-learner's coefficients (Group A) an interpretable baseline: how good is each base model in isolation, versus how much weight does the meta-learner actually give it.

Group A — 6 iterations

Stacking meta-learner (next step 5)

Out-of-fold predictions from 3-4 base models (tuned LightGBM, tuned Random Forest, default XGBoost, optionally logistic regression) are stacked into a small feature matrix; a logistic-regression meta-learner is trained on that matrix against the real labels, replacing the flat probability average every ensemble in this project has used until now. Run at both horizons, with and without the weak logistic-regression base member, plus — since the 10-day result looked competitive — an adaptive regularization-strength follow-up (not pre-registered; triggered by this round's own results).

Group B — 2 iterations

Support-filter threshold push (next step 6)

Each horizon's tuned single-model winner, evaluated on the frozen holdout at four support levels (≥30, the established floor; ≥50, ≥100, ≥150 historical events for that cell) — one real model fit per horizon, sliced four ways on the same predictions.

Group C — 6 iterations

Two-stage severity, mega features + tuned models (next steps 2/3)

Round 3's two-stage architecture (P(any event) × P(severe | event occurs)) rebuilt on the 60-column mega feature set with the new tuned models, instead of round 3's original, weaker feature set and 3-way ensemble. Includes the "LightGBM specifically for severity" test at the horizon where it hadn't been tried (14-day stage 2), its reverse (Random Forest as stage 2 at 10-day), and single-stage LightGBM severity controls at both horizons to confirm round 3's original two-stage-is-necessary finding still holds on the richer feature set.

Group D — 2 iterations

WorldPop population feature (next step 4)

The real, partial (46.1% cell coverage) population feature added to each horizon's tuned winner, evaluated honestly at that coverage level rather than waiting for the full download.

Group E — 4 iterations

Combined best-of-round6 configuration

The script decides programmatically, from its own Groups A and D results, whether stacking and WorldPop each earned a place in a final combined configuration per horizon (stacking used only if its holdout precision beat the known tuned-single baseline; WorldPop used only if its holdout precision beat the baseline at either horizon) — then extends that combined configuration to severity. This is the "suggest what's promising for the next iteration, then actually run it" step, decided by the data rather than pre-written.

Most promising, confirmed

Stacking works at 10-day, for a specific, explainable reason

The meta-learner's own coefficients tell a consistent story across all six stacking fits: Random Forest and XGBoost carry real, large positive weight (typically 1.5–3.3) while LightGBM's weight collapses to near zero or slightly negative (-0.06 to +0.48), despite LightGBM being the best solo model at 10-day (72.4% for XGBoost solo vs. 76.1% for tuned LightGBM solo). This isn't a contradiction: it means LightGBM's predictions are highly correlated with what RF and XGB already contribute once those two are both in the mix — its solo skill is real, but it adds little the meta-learner can't already get more cheaply from the other two. Dropping logistic regression (A3, no weak base member) outperformed keeping it (A1) by 1.3 points, and the regularization sweep (A5) showed the meta-learner itself is not sensitive to its own hyperparameter — the real lever here is which base models are stacked, not how the meta-learner is tuned.

Most promising, confirmed

Support-filtering remains the single best lever in this whole project

Every configuration tested this round, at every horizon, gets a real precision-and-recall improvement from filtering to well-established cells — now validated up to a ≥100 floor at both horizons (10-day: 76.1%→79.6% combined with stacking; 14-day: 75.5%→78.1%), a genuinely larger effect than any single model or feature change tried in rounds 3 through 6. It is also the first lever in this project to show a real reversal: pushing 10-day to ≥150 support lost precision (75.0%, below even the ≥100 result), meaning the optimum floor is itself horizon-specific and needs to be selected per deployment, not maximized blindly.

Real negative result

WorldPop, at 46% coverage, did not deliver on the prior round's speculation

The prior round's writeup flagged WorldPop as "the more promising kind of lever" specifically because it's a structurally different signal (population density) rather than more slicing of existing UCDP/GDELT signal. Tested for real this round at 46.1% real coverage, it underperformed the no-WorldPop baseline at 10-day (74.0% vs. 76.1% alone; 78.2% vs. 78.8% combined with stacking) and was statistically flat at 14-day. The most likely explanation, worth testing directly once the download completes: at 46% coverage roughly half of every holdout batch gets a filled-zero placeholder rather than a real population value (the same fillna(0) convention used for every feature in this pipeline), which a tree-based model can plausibly read as "very low population" for countries that are actually unmeasured rather than genuinely sparse — mixing a real signal with a systematic missing-data artifact. This is disclosed as a real negative result at this coverage level, not a verdict on the underlying hypothesis.

Consistent theme, again

No lever wins both horizons, and the winning lever type differs by horizon

Stacking is a real 10-day win and a real 14-day non-win. Support-filtering helps both horizons but with different optimal floors. This is the fourth round in a row (following the "no single model wins both horizons" finding from the grand search, and rounds 3-4's per-horizon feature sensitivity) to find that 10-day and 14-day are not the same task wearing different labels — they respond to different levers, not just different model weights, and should keep being tuned and evaluated separately rather than merged into one "the" configuration.

The question underneath every number in this report

Two genuinely different forecasting tasks live in this project

This project has produced results for two structurally different questions. It matters which one a reviewer thinks they're reading, because the headline precision numbers are not directly comparable across them — and DARPA's own program page is explicit about which one it specified.

Country-week escalation

"Will this whole country see an unusually active week, next week?"

  • Unit of prediction: one of 19 countries × one week ahead.
  • Label: a statistical anomaly flag — that country's own event count or fatality count next week exceeding its trailing historical average by more than a fixed margin (a relative, self-referential threshold, not an absolute event).
  • Output: a single yes/no flag per country per week. No date, no place within the country, no event type.
  • Base rate: 37.8% of country-weeks (324 of 858) — a coin-flip-adjacent problem.
  • Validated result (Criterion 2, this project): 84.0% precision, 56.8% recall, on 858 real country-week predictions.
Discrete geolocated events

"Will a real, dated event occur in this specific ~55km grid cell, in the next 10 or 14 days?"

  • Unit of prediction: one of 464 real PRIO-GRID cells (~55km, the same grid ViEWS uses) × a rolling 10- or 14-day forward window.
  • Label: a real, absolute event — at least one dated, geolocated, UCDP/ACLED-style conflict event actually occurring in that specific cell within the window.
  • Output: a flagged (place, time-window) pair — directly matching what an ACLED/UCDP-style event feed itself contains.
  • Base rate: 8.7% of (cell, window) pairs in the 10-day holdout — a genuinely rare-event problem.
  • Best validated result (this round): 79.6% precision, 25.4% recall, support-filtered, 10-day; 78.1%/32.6%, 14-day.
Why the numbers aren't directly comparable, in one sentence: asking "did anything unusual happen anywhere in this whole country" is intrinsically easier than asking "did something happen in this one specific 55km patch of it" — the country-week task's 37.8% base rate versus the discrete-event task's 8.7% base rate is most of that gap, not model quality. Precision-at-similar-thresholds looks superficially close (84.0% vs. ~76-80%) specifically because the discrete task is being asked at ~4x the spatial and temporal specificity for a comparable precision bar, which is why its recall (8-33%, depending on support-filtering) is so much lower than the country-week figure's 56.8% — there are far more (place, time) cells to be right about, and each one is individually rarer.
Verbatim, from the source

What DARPA's program page actually specifies

From darpa.mil/research/programs/predicting-forecasting-high-confidence (the "Art of Novel Signals" SBIR topic), read directly for this report:

"…ACLED style political and conflict events…" — the event type DARPA's program page specifies the system should forecast

ACLED (the Armed Conflict Location & Event Data project) is, by construction, a database of individual, dated, geolocated, typed conflict events — not a country-level weekly anomaly flag. UCDP GED, the data source this project's discrete-event pipeline actually uses, is the same category of dataset (dated, geolocated, actor-coded events), which is why this project's discrete-event task — not its country-week escalation task — is the one built to produce the kind of output this sentence describes.

"Central and Southeast Asia, East and Northeast Africa, and South America" — the three regions the program targets

Matches this project's 19-country set directly: Afghanistan/Myanmar/Pakistan/Tajikistan/Kyrgyzstan/Uzbekistan (Central & Southeast Asia), Sudan/Ethiopia/Somalia/South Sudan/Kenya/Eritrea (East & Northeast Africa), Colombia/Venezuela/Ecuador/Peru/Bolivia/Haiti/Nicaragua (South America, plus Haiti).

"…demonstrate a 10-day forecasting horizon…" (Month 6) / "…Demonstrate the two-week horizon…" (Month 9) — the named lead times, and the exact language this project's "10-day" and "14-day" horizons were chosen to match
Baseline precision "approximately 80%" across regions; the novel-signal approach targets "raise this precision level up to 90%" — the precision bar this whole project, including every number in this report, has been measuring itself against
"Precision alone is an incomplete measure" — DARPA's own caveat, and the reason this report leads every result with both precision and recall, and reports the support-filtering recall trade-off explicitly rather than only the headline precision figure
The direct answer

Which task did DARPA ask for?

The discrete, geolocated, grid-cell event forecasting task — the one this darpa_event_forecasting/ folder and this round's 24 iterations are built around — is the one that matches the program page's own language: dated, geolocated, ACLED-style events, at named 10-day and two-week horizons, across the same three named regions. The country-week escalation classifier (Criterion 2's 84.0%/56.8% headline result, currently the number cited in the DARPA proposal draft) answers a real and useful but structurally different, coarser question — "is this country having an unusually active week" — that does not produce an ACLED-style output and was not the granularity DARPA's page specifies. This is the same gap the darpa_event_forecasting folder's own README identified as the reason it exists in the first place; 181 real logged iterations later (157 in the grand search, 24 in this round, on top of rounds 1-5's own separately-logged runs), the gap in what's specified versus what's currently the proposal's headline number remains open, and closing it is a scope decision for the proposal, not a modeling one.

Prioritized

What this round's own results suggest trying next

  1. 1

    Deploy 3-base stacking (10-day) + tuned RF (14-day), both support-filtered at ≥100

    The best validated combination found across all six rounds: 79.6%/25.4% (10-day), 78.1%/32.6% (14-day) — free, no new data, purely a configuration and slicing change.

  2. 2

    Finish the WorldPop download, then re-test at full coverage

    This round's negative result is specific to 46% coverage and a zero-fill convention for missing countries; a coverage indicator feature (rather than raw population with a zero-fill) is a cheap, testable fix worth trying alongside full coverage.

  3. 3

    Search around the ≥100/≥150 support-filter boundary directly

    The 10-day reversal between ≥100 and ≥150 wasn't expected and hasn't been explained; a finer sweep (≥75, ≥125) would clarify whether it's a real inflection or holdout-sample noise at the smaller n.

  4. 4

    Try stacking specifically on the support-filtered population, not just the whole holdout

    Both winning levers (stacking, support-filtering) were validated independently this round but never jointly re-optimized — the meta-learner was fit on the whole select window, not a support-filtered one, which is untested.

  5. 5

    Decide the escalation-vs-discrete-event scope question explicitly

    Tab 05's gap is a proposal decision, not a modeling one: whether Criterion 2's country-week figure, the discrete-event figures in this report, or both, become the submitted precision claim — each implies a different reviewer question to be ready for.
