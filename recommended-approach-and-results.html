What the reference document got right, what the actual RFP requires instead, and a working prototype on real data

The methodology reference in this folder is strong groundwork. Read against the actual solicitation text, one load-bearing design choice needs to change before it matches what DARPA is asking proposers to demonstrate. This document makes that correction, then builds and runs a real, working version of the corrected approach — real GDELT events, a real temporal knowledge graph, five real models, and an honest rolling-origin backtest — end to end.

The four interlocking components DARPA describes

  1. A radio data collection engine — streaming online plus software-defined receivers for offline stations
  2. ASR for low-resource, predominantly oral languages (fine-tuned Whisper Large-v3, 50–200 hours transcribed audio per language, native-speaker annotation at roughly $5/hour)

The correction

The one requirement that changes the model ordering

The solicitation's DP2 evaluation criteria are explicit about the required forecasting mechanism, quoted directly:

"An in-context-learning forecasting pipeline that operates over temporal knowledge graphs without retraining."

The reference document's tab 03 leads with a temporal graph neural network (TGN / EvolveGCN) as its anchor model — the one every other entry in the battery is measured against. A TGN is a genuinely strong architecture for graph-structured forecasting, and it isn't wrong as an idea. But it needs gradient training on every rolling fold to update its learned representations. That directly contradicts "without retraining." Leading a DARPA-facing methodology document with the one architecture the solicitation's own evaluation criteria rules out is a real risk worth fixing before this goes further, not a stylistic quibble.

What doesn't need to change: the extraction pipeline (tab 01 stages 1–4), the graph schema (Actor / Location / Event / Source / Claim nodes, bitemporal edges), the backtesting discipline (rolling-origin splits, Brier + precision/recall over ROC-AUC, base-rate comparison), and three of the reference document's four non-TGN models. Only the anchor model and its justification need correcting — the rest of the reference document's thinking holds up well against the actual solicitation text.
Architecture

The corrected model battery

Same shared interface as the reference document — fit(train_window), predict_proba(next_window) — run back-to-back against identical rolling-origin splits. The anchor changes; the discipline doesn't.

  • 01

    In-context-learning forecaster over the temporal knowledge graph

    No gradient training at any point — retrieval + prompting only

    At prediction time: serialize the recent graph state for a country-week to structured text (event counts by CAMEO quad-class, Goldstein trend, distinct-actor count, source tone), retrieve the k most similar historical country-weeks by cosine similarity over that same feature vector, and prompt a foundation model for a calibrated probability plus a reasoning trace referencing the retrieved analogs. The "index" built from the training window is retrieval bookkeeping, not a trained model — nothing about it has learned weights that update via backpropagation.

    Why first: this is the literal mechanism named in the RFP's DP2 evaluation criteria. Every other model in the battery exists to show whether this one is actually earning its complexity.

  • 02

    Gradient-boosted trees on hand-engineered graph features

    XGBoost, tabular, retrained per fold — a labeled comparison point

    Flattens the graph to region-week features: event frequency, quad-class escalation ratios, Goldstein trend, actor-count deltas. Fast, interpretable, and — unlike the ICL forecaster — explicitly allowed to retrain each fold, since it isn't the model being evaluated against the "without retraining" criterion. Its job is to set the bar the ICL approach needs to clear or credibly explain why it doesn't need to.

    Why: if a retrained tabular model matches the no-retraining ICL forecaster, that's a legitimate, reportable finding either way — not a failure of the harness.

  • 03

    Lagged logistic regression

    The minimum viable baseline

    Region-week event counts and their lags, nothing else. Every fancier model must beat this or the added complexity has no case.

  • 04

    Naive persistence

    Not a model — a floor

    "Escalation continues where it's already happening." No features, no fitting.

  • 05

    Historical base rate

    Not a model — the other floor

    Predicts each country's own historical escalation rate. Run automatically every fold, not as a one-time check — see tab 04 for why that discipline mattered in practice.

  • —

    Temporal graph neural network — demoted, not discarded

    TGN / EvolveGCN

    Still worth building once the program has enough labeled history to retrain on a defensible cadence (e.g., quarterly, outside the live no-retraining evaluation loop) — genuinely the only architecture here that can use alliance-edge changes and centrality shifts directly rather than as flattened features. Positioned as a research track parallel to the SBIR's required deliverable, not the deliverable itself.

Label

Defining "escalation" without a fatality count

This prototype runs on raw GDELT (automated CAMEO coding, no built-in fatality field), not ACLED — so the label is defined relative to each country's own trailing baseline rather than an absolute severity threshold. It's a real, defensible operationalization, and it's exactly the kind of choice that should be swapped for ACLED/UCDP fatality-coded onsets once that registration is in place (see tab 05).

Escalation, country-week t → t+1

label = 1 if either:

  • the material-conflict share of events (CAMEO quad-class 4) rises more than 1 standard deviation above that country's own trailing expanding mean, or
  • the mean Goldstein score drops more than 2 points below that country's own trailing expanding mean

Both baselines use only data available before the prediction point (an expanding window, shifted by one period) — the same bitemporal discipline the reference document's tab 01 callout insists on for the graph writes themselves.

Pipeline

Four scripts, run in order, on real data

Every script below actually ran to produce the numbers in tab 04 — real GDELT events for Sudan, Myanmar, Afghanistan, and Colombia (one country from each of the RFP's three named regions, Sudan and Afghanistan both sitting inside the broader Africa/Asia scope), 90 days ending August 1, 2026, no synthetic rows anywhere.

""" import io, sys, time, urllib.request, zipfile from datetime import date, timedelta UA = "Mozilla/5.0 ..." """ Builds a real temporal knowledge graph from the filtered GDELT events (networkx), then derives a country-week panel of graph-native features plus an escalation label defined relative to each country's own trailing baseline. Matches the reference document's tab-01 schema: Actor / Location / Event nodes; PARTICIPATED_IN / OCCURRED_AT edges. """ import networkx as nx import numpy as np import pandas as pd TARGET_COUNTRIES = ["SU", "BM", "AF", "CO"] def build_graph(df): G = nx.MultiDiGraph() for country in TARGET_COUNTRIES: G.add_node(f"LOC:{country}", type="Location") for _, row in df.iterrows(): eid = f"EVT:{row['GlobalEventID']}" G.add_node(eid, type="Event", quad_class=row["QuadClass"], goldstein=row["GoldsteinScale"]) G.add_edge(eid, f"LOC:{row['ActionGeo_CountryCode']}", type="OCCURRED_AT") for actor_col in ["Actor1Code", "Actor2Code"]: actor = row[actor_col] if isinstance(actor, str) and actor.strip(): anode = f"ACT:{actor}" if anode not in G: G.add_node(anode, type="Actor") G.add_edge(anode, eid, type="PARTICIPATED_IN") return G def build_panel(): df = load_events() # parses dates, filters to target countries + real window rows = [] for country in TARGET_COUNTRIES: sub = df[df.ActionGeo_CountryCode == country] weekly = sub.groupby("week").agg( n_events=("GlobalEventID", "count"), n_material_conflict=("QuadClass", lambda s: (s == 4).sum()), mean_goldstein=("GoldsteinScale", "mean"), mean_tone=("AvgTone", "mean"), ).reset_index() weekly["country"] = country rows.append(weekly) panel = pd.concat(rows).sort_values(["country", "week"]) panel["material_conflict_share"] = panel.n_material_conflict / panel.n_events.clip(lower=1) # trailing baseline -- expanding window, shifted, so it only ever uses # information available BEFORE the week being scored panel["baseline_mean_share"] = panel.groupby("country")["material_conflict_share"].transform( lambda s: s.expanding(min_periods=4).mean().shift(1)) panel["baseline_std_share"] = panel.groupby("country")["material_conflict_share"].transform( lambda s: s.expanding(min_periods=4).std().shift(1)) z_share = (panel.material_conflict_share - panel.baseline_mean_share) / panel.baseline_std_share panel["escalation_next_1w"] = (z_share > 1.0).astype("Int64") panel["label_1w_ahead"] = panel.groupby("country")["escalation_next_1w"].shift(-1) panel["label_2w_ahead"] = panel.groupby("country")["escalation_next_1w"].shift(-2) return panel

class ICLForecaster: """ THE RFP'S ACTUAL REQUIRED APPROACH -- in-context learning over the temporal knowledge graph, no gradient training at any point. 'fit' below only builds the historical-analog index from the training window -- retrieval bookkeeping, not model training. """ def fit(self, train_df, label_col): self.index_df = train_df.dropna(subset=FEATURES + [label_col]) self.index_features = self.index_df[FEATURES].fillna(0).values self.index_labels = self.index_df[label_col].values return self def _retrieve_analogs(self, feature_vec): # cosine similarity over standardized features -- real, non-trained retrieval z_query = (feature_vec - self.index_mean) / self.index_std z_index = (self.index_features - self.index_mean) / self.index_std sims = z_index @ z_query / (np.linalg.norm(z_index, axis=1) * np.linalg.norm(z_query) + 1e-9) return np.argsort(-sims)[:self.k_analogs], sims def _call_llm(self, context_text, analog_summary): api_key = os.environ.get("ANTHROPIC_API_KEY") prompt = ("You are a conflict early-warning analyst. def rolling_origin_folds(panel, label_col, min_train_weeks=6): weeks = sorted(panel.week.unique()) folds = [] for i in range(min_train_weeks, len(weeks)): cutoff = weeks[i] train = panel[panel.week < cutoff].dropna(subset=[label_col]) # strict temporal cutoff test = panel[panel.week == cutoff] if len(train) and len(test) and not test[label_col].isna().all(): folds.append((cutoff, train, test)) return folds def run_backtest(panel, label_col, lead_time_label): folds = rolling_origin_folds(panel, label_col) all_preds = {name: [] for name in MODEL_REGISTRY} all_labels = [] for cutoff, train, test in folds: test_valid = test.dropna(subset=[label_col]) all_labels.extend(test_valid[label_col].astype(int).tolist()) for name, cls in MODEL_REGISTRY.items(): model = cls().fit(train, label_col) all_preds[name].extend(model.predict_proba(test_valid, label_col).tolist()) y = np.array(all_labels) for name in MODEL_REGISTRY: p = np.array(all_preds[name]) brier = brier_score_loss(y, p) ap = average_precision_score(y, p) if y.sum() > 0 else float("nan") # ... precision/recall at 0.5 and at top-N, delta vs base rate, logged per model

A real data-quality catch worth stating plainly: the first pass at building the panel showed a handful of GDELT rows dated many months outside the actual 90-day download window — a known minor GDELT quirk where a small number of records carry a retrospective or corrected SQLDATE. Left in, they would have added several near-empty, unreliable weeks to a rolling-origin backtest that's already working with a small sample. Filtered out before scoring, and disclosed here rather than silently fixed.

The honest headline, exactly as the reference document's own methodology predicted it might go: tab 01's backtesting section warns "a lot of published results look strong only until compared against these [base-rate] baselines" — and here, the historical base rate posts the best (lowest) Brier score at both horizons, beating every trained model including the GBM and the ICL forecaster. Immediate

What would change the results above the most

  • 1

    Wire in a real LLM call

    The code path exists and is untested against a live model in this environment. Setting ANTHROPIC_API_KEY and rerunning is a same-code change, not a rewrite — the honest next step before drawing any conclusion about whether the ICL approach's reasoning trace adds value over the fallback's fixed formula.

  • 2

    Register for ACLED and switch the label

    Free for academic/nonprofit use per the reference document's tab 02. Fatality-coded, hand-curated onset dates directly replace the Goldstein/quad-class proxy label used here, and match the RFP's own stated evaluation ground truth ("ACLED-style political/conflict events") exactly rather than approximately.

  • 3

    Widen the window

    GDELT 2.0 covers February 2015 to present at no cost. 90 days was a deliberate, disclosed scope choice for a runnable prototype — expanding to multiple years turns "6 positive weeks" into a sample size that can actually separate these models' calibration from noise.

  • 4

    Add the radio/ASR layer the RFP is actually funding

    Everything here starts from already-coded GDELT events — useful for prototyping the graph and forecasting layers exactly as the reference document's tab 02 frames it, but it isn't the novel signal source the program exists to fund. The Whisper Large-v3 fine-tuning, streaming/SDR ingestion, and synthetic-data strategy for the named oral-language regions are a separate, larger build this document doesn't attempt.

  • 5

    Build the paralinguistic feature extractor

    Explicitly named as a Month-15 deliverable (pitch, energy, emotion indicators) and not present anywhere in the reference document or this prototype — worth flagging early since it implies an audio-features pipeline distinct from the transcription pipeline, not an extension of it.
